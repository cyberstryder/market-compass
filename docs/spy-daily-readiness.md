# SPY daily ATR readiness repair — September 21, 2026

Production evidence before repair: the September 21 opening and all three later checks were blocked by `prior daily ATR evidence incomplete`. Frozen PM high was 767.26; saved closes were 766.86, 767.69, 767.79 and 769.03 at 08:45/09:00/09:15/09:30 CT. The latter three met the underlying breakout condition. No option return is reconstructed or claimed.

The old reader limited raw daily archive records to 90 before grouping by trading day. Archive keys include the payload, so revisions can exhaust that limit and hide required sessions. A regression with 100 Friday revisions and all 15 required sessions present returned null ATR under the old reader. This establishes the software defect, not a census of the original production archive at decision time.

The new reader ranks rows within the 15 required completed exchange sessions before selecting each latest revision. It excludes current-day bars and validates OHLCV. All 15 sessions remain required for the original 14-value mean true range calculation. Invalid latest revisions are not silently replaced with earlier data. Evidence records required/usable/missing dates and selected event IDs.

An independent collector checks SPY readiness every minute from 06:00 New York through the equity close. It avoids the all-watchlist minute-history queue. When blocked, it requests only the required SPY daily date range (one unpaginated, split-adjusted provider request per iteration), validates the complete response structure and each returned bar, and persists real bars through the existing archive path. Missing provider sessions stay blocked and are retried; no synthetic bars or ATR fallback. The scheduled collector's existing exception backoff handles provider errors. Health and runtime records show readiness plus how many required sessions the legacy 90-row reader can see.

New daily plans are version v4. Data-blocked decisions and Discord headings explicitly identify DATA BLOCKED; detailed reports include missing dates and usable-session count. Existing WAIT/no-entry state transitions remain compatible with follow-up registration. A completed morning window stays completed: deployment does not replay alerts or rewrite historical decisions/trades. Existing frozen timeframe records are not rewritten or used to tune thresholds. The read-path correction applies prospectively to newly computed inputs.

Validation includes original failing revision-starvation reproduction, exact holiday/weekend coverage, current-day exclusion, independent preopen recovery, ready-cache behavior, invalid/paginated/duplicate/future-day response rejection, partial-source blocking, invalid latest revisions, and recovery into a later confirmation without changing the saved opening report. This release does not introduce faster entries or new strategy families.
